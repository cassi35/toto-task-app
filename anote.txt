. POST /auth/signup (Cadastro)
    Decorador: @Public()
    Corpo (Body): CreateUserDto (email, password).
    O que faz: Cria o usuário no banco de dados (usando hash de senha com bcrypt) e, opcionalmente, já retorna os tokens de acesso para o usuário não precisar logar logo após se cadastrar.

2. POST /auth/login (Login)
    Decorador: @Public()
    Corpo (Body): AuthDto (email, password).
    O que faz: Valida as credenciais. Se estiverem corretas, gera o par de tokens: Access Token (curta duração) e Refresh Token (longa duração).
    Dica: O Refresh Token deve ser enviado via Cookie HttpOnly para segurança.

3. POST /auth/logout (Sair)
    Decorador: Privado (Não usa @Public()).
    Corpo: Vazio.
    O que faz: Invalida o Refresh Token do usuário no banco/Redis e limpa o cookie do navegador. Como é privada, você usa o @GetUser('id') para saber quem está saindo.

4. POST /auth/refresh (Atualizar Token)
    Decorador: Privado (Mas usa um Guard específico para Refresh Token, o RtGuard).
    Corpo: Vazio (lê do cookie ou header).
    O que faz: Quando o Access Token expira, o frontend chama essa rota para obter um novo Access Token sem pedir a senha do usuário novamente.

5. POST /auth/forgot-password (Esqueci a Senha)
    Decorador: @Public()
    Corpo: { "email": string }.
    O que faz: Gera um token temporário, salva no banco com expiração (ex: 15 min) e envia um link de recuperação por e-mail.

6. POST /auth/reset-password (Redefinir Senha)
    Decorador: @Public()
    Corpo: { "token": string, "newPassword": string }.
    O que faz: Valida o token enviado por e-mail. Se for válido, atualiza a senha do usuário e deleta o token de recuperação.
