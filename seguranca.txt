SEGURANÇA – GITHUB + PROJETO
1. GITHUB
 Repositório privado (se não for open source)
 .gitignore configurado (.env, node_modules, dist, etc.)
 Nunca commitar secrets (tokens, senhas, chaves)
 Ativar 2FA na conta
 Usar GitHub Secrets para variáveis sensíveis (Actions)
 Revisão obrigatória de PR (branch protection)
 Desabilitar push direto na main
 Dependabot ativado (atualizações de libs)
 Code scanning ativado (CodeQL)
 Verificar histórico (se já vazou secret → rotacionar)
2. SECRETS / ENV
 Usar .env local (nunca subir)
 .env.example sem valores reais
 Variáveis separadas por ambiente (dev/staging/prod)
 Rotação periódica de secrets
 Não logar secrets no console
 Não retornar secrets em API
 Usar cofre de segredo (ex: AWS Secrets Manager, Vault)
 Validar env na inicialização (ex: zod, joi)
3. BACKEND (API)
 Validação de input (DTO + validation pipe)
 Sanitização de dados (evitar injection)
 Rate limiting
 CORS restrito
 Helmet (headers de segurança)
 Autenticação (JWT com expiração curta)
 Refresh token seguro (httpOnly cookie)
 Autorização (roles/permissions)
 Logs sem dados sensíveis
 Tratamento de erro sem expor stack
4. POSTGRESQL
 Usuário sem superuser (least privilege)
 Senha forte
 Conexão com SSL
 Porta não exposta publicamente
 Backup automático
 Rotação de credenciais
 Evitar SQL raw (usar ORM ou prepared statements)
 Limitar conexões
 Separar DB por ambiente
5. DOCKER
 Não usar latest (fixar versão)
 Usar imagem base mínima (ex: alpine)
 .dockerignore configurado
 Não copiar .env para imagem
 Rodar como usuário não-root
 Multi-stage build
 Scan de vulnerabilidade (Trivy, etc.)
 Secrets via runtime (não no build)
 Porta exposta apenas se necessário
6. CI/CD (GitHub Actions)
 Usar secrets do GitHub (não hardcoded)
 Permissões mínimas (permissions: no workflow)
 Não expor logs com dados sensíveis
 Validar PR antes de merge (test, lint)
 Rodar testes automatizados
 Bloquear execução de forks (se necessário)
 Cache seguro (sem incluir secrets)
7. AUTENTICAÇÃO / SESSÃO
 Senhas com hash (bcrypt)
 Nunca salvar senha em texto puro
 JWT com expiração
 Refresh token armazenado seguro
 Logout invalida token
 Proteção contra brute force
8. FRONTEND
 Não expor secrets no client
 Usar apenas variáveis públicas (NEXT_PUBLIC_)
 Proteção contra XSS
 Sanitizar inputs
 HTTPS obrigatório
 Não confiar no client (validar no backend)
9. INFRA / PRODUÇÃO
 HTTPS (TLS)
 Firewall ativo
 Monitoramento (logs + alertas)
 Rate limit no gateway
 Atualizações de segurança
 Isolamento de serviços (containers)
10. GERAL
 Princípio do menor privilégio (least privilege)
 Rotação de chaves
 Auditoria de acessos
 Teste de segurança (pentest básico)
 Backup testado (restore funcionando)
 Plano de incidente (se vazar algo)

 CHECKLIST AVANÇADO (nível produção real)
1. MODELAGEM DE AMEAÇAS
 Mapear endpoints críticos (auth, pagamento, dados)
 Identificar ativos (DB, tokens, arquivos)
 Listar possíveis ataques (OWASP Top 10)
 Definir impacto (alto/médio/baixo)
 Definir mitigação por risco
2. AUTENTICAÇÃO / AUTORIZAÇÃO (crítico)
 JWT com expiração curta (5–15 min)
 Refresh token rotativo (invalidate antigo)
 Armazenar refresh em httpOnly cookie
 Blacklist de tokens (logout / revoke)
 RBAC (roles) ou ABAC (regras)
 Verificação de autorização em TODAS rotas
 MFA (se aplicável)
 Proteção contra brute force (rate limit + lock)
3. VALIDAÇÃO E INPUT (anti-injection)
 Validação global (DTO + schema)
 Sanitização (XSS)
 Nunca confiar no frontend
 Limite de tamanho de payload
 Upload de arquivos validado (tipo + tamanho)
 Bloquear SQL raw (usar prepared/ORM)
4. SEGURANÇA DE API
 Rate limit por IP + user
 Timeout em requests externos
 Circuit breaker (falhas externas)
 Idempotência (evitar duplicação crítica)
 Logs estruturados (sem dados sensíveis)
 Erros genéricos (não expor stack)
5. BANCO (POSTGRES)
 Usuário com permissão mínima
 Row Level Security (RLS) se necessário
 Criptografia em trânsito (SSL)
 Criptografia em repouso (se cloud)
 Auditoria de queries sensíveis
 Backup + restore testado
 Segregar DB (dev/staging/prod)
6. DOCKER / CONTAINER
 USER não-root
 Imagem mínima (alpine/distroless)
 Scan de vulnerabilidade (Trivy)
 Remover ferramentas desnecessárias (curl, bash)
 Secrets via runtime (env/secret manager)
 Limitar CPU/memória
 Network isolada
7. CI/CD (pipeline seguro)
 SAST (scan código)
 DAST (scan runtime)
 Dependency scan (vuln libs)
 Bloquear merge se falhar segurança
 Assinatura de artefatos (supply chain)
 Permissões mínimas no workflow
 Segredo nunca em log
8. MONITORAMENTO / DETECÇÃO
 Logs centralizados (ELK, etc.)
 Alertas (ex: login suspeito)
 Métricas (latência, erro, spikes)
 Detecção de anomalia
 Auditoria de acesso
9. INFRA / REDE
 HTTPS obrigatório (TLS 1.2+)
 HSTS ativado
 Firewall (bloquear portas)
 WAF (Cloudflare, etc.)
 VPN ou IP allowlist para admin
 Segmentar rede (DB não público)
10. FRONTEND
 CSP (Content Security Policy)
 Proteção XSS/CSRF
 Cookies com Secure, HttpOnly, SameSite
 Não armazenar token em localStorage (preferir cookie)
 Build sem expor variáveis privadas
11. GOVERNANÇA
 Rotação de secrets automática
 Acesso por função (IAM)
 Auditoria periódica
 Plano de incidente (vazamento, ataque)
 Treino básico de segurança
